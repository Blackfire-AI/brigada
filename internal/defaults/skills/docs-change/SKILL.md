# docs-change

1. Write in the present tense, describing the system as it is.
2. Verify the text against the code: names, flags, defaults, paths and
   behavior must match what the code does.
3. Run the commands the documentation names, in the form it gives
   them, and fix what does not work as written.
4. Check that cross-links hold: anchors, file paths and references
   point at what they name.

If your tools can run the relevant tests, commands, or checks, do it; otherwise verify by inspection and say so in the summary.
